# projects/

Cross-cutting initiatives that aren't scoped to a single client or a single repo — the kind
of thing that would otherwise have no home. Examples: VisWoX product roadmap/direction,
a migration or upgrade effort that touches multiple clients, internal tooling work.

One file per initiative: `<slug>.md`. If something is really about one client's engagement,
it belongs in `clients/` instead; if it's implementation planning for one codebase, it likely
belongs in that repo's own `docs/` (see `viswox`'s `docs/superpowers/` spec-then-plan
convention) rather than here.
